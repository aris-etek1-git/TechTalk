# TECHTALK

## Cahier des charges fonctionnel et technique

**Version : 1.0**

---

# 1. VISION DU PROJET

## 1.1 Concept

TechTalk est une plateforme de découverte, d'apprentissage, de pratique et de connexion destinée principalement aux développeurs et aux étudiants en informatique.

TechTalk ne cherche pas à remplacer YouTube, Reddit, GitHub, LeetCode, Codeforces, les écoles, les enseignants ou les plateformes de formation.

TechTalk constitue une **couche de découverte et d'organisation au-dessus de ces plateformes**.

L'utilisateur doit pouvoir découvrir au même endroit :

* des vidéos ;
* des discussions ;
* des articles ;
* des projets ;
* des repositories ;
* des exercices ;
* des compétitions ;
* des cours ;
* des livres ;
* des papers ;
* des événements ;
* des personnes ;
* des mentors ;
* des stages ;
* des bourses ;
* des opportunités.

Le contenu reste hébergé sur sa plateforme d'origine lorsque cela est pertinent.

Exemple :

```text
TechTalk
   ↓
"10 exercices de graphes"
   ↓
LeetCode
```

ou :

```text
TechTalk
   ↓
"Understanding Transformers"
   ↓
YouTube
```

ou :

```text
TechTalk
   ↓
"Excellent projet de moteur 3D"
   ↓
GitHub
```

---

# 2. PROBLÈME

Le contenu destiné aux développeurs est extrêmement fragmenté.

Un étudiant peut devoir utiliser simultanément :

* YouTube pour apprendre ;
* Reddit pour discuter ;
* GitHub pour construire ;
* LeetCode pour pratiquer ;
* Codeforces pour les compétitions ;
* Kaggle pour la Data/IA ;
* Stack Overflow pour résoudre des problèmes ;
* des blogs pour lire ;
* des papers pour la recherche ;
* LinkedIn pour les opportunités ;
* son école pour le programme ;
* des plateformes externes pour les cours ;
* des enseignants ou mentors pour obtenir de l'aide.

Le problème n'est donc pas seulement l'accès à l'information.

Le problème est :

> **trouver la bonne information, la bonne personne, le bon exercice ou la bonne opportunité au bon moment.**

---

# 3. OBJECTIF PRINCIPAL

TechTalk doit progressivement répondre à une question :

> **"Compte tenu de ce que je suis, de ce que j'apprends, de ce que je construis et de ce que je veux devenir, qu'est-ce qui est pertinent pour moi maintenant ?"**

Le système doit donc évoluer vers une personnalisation basée sur :

* intérêts ;
* niveau ;
* formation ;
* école ;
* programme ;
* historique ;
* comportements ;
* projets ;
* compétences ;
* objectifs ;
* contexte.

# 7. PRINCIPE IMPORTANT : TECHTALK N'HÉBERGE PAS TOUT

TechTalk ne doit pas devenir un gigantesque stockage de vidéos.

Pour les contenus externes :

```text
Source externe
      ↓
API
      ↓
normalisation TechTalk
      ↓
base de données / cache
      ↓
TechTalk
      ↓
plateforme originale
```

TechTalk stocke principalement :

* identifiants externes ;
* titres ;
* descriptions ;
* miniatures ;
* auteurs ;
* tags ;
* statistiques nécessaires ;
* dates ;
* URLs ;
* métadonnées ;
* informations utiles à la recommandation.

# 11. ÉVOLUTION DU SYSTÈME DE RECOMMANDATION

TechTalk ne doit pas commencer par un système ML complexe.

## Niveau 0 — chronologique

```text
plus récent
↓
plus ancien
```

## Niveau 1 — popularité

Utiliser :

* likes ;
* commentaires ;
* vues ;
* réactions ;
* popularité externe.

## Niveau 2 — tags

Comparer :

```text
UserInterest
      ↓
ContentTags
```

## Niveau 3 — comportement

Signaux :

```text
view
watchTime
completionRate
like
save
share
click
skip
```

## Niveau 4 — scoring hybride

Exemple conceptuel :

```text
score =
    tagMatch
  + popularity
  + freshness
  + interactionHistory
  + diversity
```

## Niveau 5 — Machine Learning

Plus tard :

```text
features
   ↓
modèle ML
   ↓
probabilité d'interaction
   ↓
ranking
```

Le ML sera développé séparément, notamment en Python.

# 57. PAGINATION

Utiliser la pagination par curseur pour :

* feed ;
* recherche ;
* Reddit ;
* contenus ;
* notifications.

Reddit utilise lui-même un modèle de listings avec `after`/`before`, ce qui correspond bien à une architecture de pagination par curseur.

# 58. YOUTUBE

Créer un service :

```text
YouTubeService
```

Fonctions :

```text
searchVideos()
getVideo()
getChannel()
```

La clé API reste uniquement côté serveur.

Attention aux quotas de YouTube Data API. Les appels `search.list` ont un coût de quota et les quotas doivent être gérés proprement.

Prévoir :

```text
cache
rate limiting
deduplication
```

```text
RedditService
```

Fonctions :

```text
searchPosts()

```

# 82. PRINCIPES DE CONCEPTION

TechTalk doit respecter les principes suivants :

### Simplicité

Ne pas créer une architecture complexe avant d'en avoir besoin.

### Modularité

Chaque domaine doit pouvoir évoluer indépendamment.

### Interopérabilité

TechTalk doit pouvoir intégrer de nouvelles plateformes.

### Transparence

L'utilisateur doit comprendre pourquoi quelque chose lui est recommandé lorsque cela est pertinent.

### Contrôle utilisateur

L'utilisateur peut gérer ses intérêts, préférences et données.

### Respect des plateformes externes

Les APIs et conditions d'utilisation des plateformes doivent être respectées.

### Privacy by design

Les données comportementales doivent être traitées avec précaution.

# 86. PHILOSOPHIE DU PRODUIT

TechTalk n'est pas :

> "un endroit où tout Internet est copié."

TechTalk est :

> **un système qui aide les étudiants et développeurs à découvrir ce qui existe déjà, à apprendre, à pratiquer, à construire, à rencontrer les bonnes personnes et à trouver des opportunités.**

La boucle fondamentale est :

```text

   ↓

   ↓
PRACTICE
   ↓
BUILD
   ↓
SHARE
   ↓
CONNECT
   ↓
OPPORTUNITY
   ↓
LEARN AGAIN
```

Et à mesure que TechTalk accumule des données comportementales et contextuelles, le système de recommandation évolue :

```text
RULES
  ↓
SCORING
  ↓
BEHAVIOR
  ↓
MACHINE LEARNING
  ↓
ADVANCED PERSONALIZATION
```
